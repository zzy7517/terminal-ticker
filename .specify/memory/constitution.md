# priceViewer 开发宪法

## 核心原则

### I. 本地优先
产品必须继续默认在用户本机运行。行情、配置、K 线缓存、Agent 会话和 provider 凭证都优先放在本机处理。除非新 spec 明确批准，不引入后端云服务、账号体系或多人协作存储。

### II. 图表优先的 Web 工作台
当前批准的产品形态是本地 Web 图表工作台。新增能力应服务于 watchlist、K 线图、本地策略信号和 Agent session 这条主线。不要回到 PySide 悬浮窗、折叠 ticker、滚动 ticker tape 或桌面小组件默认设计。

### III. 行情可靠性优先
陈旧、缺失、重连后补到的、占位性质的行情都不能被当成新鲜真实数据。任何依赖价格或 K 线生成的能力，比如策略信号、Agent 上下文、颜色提示和状态展示，都必须定义 stale、reconnect、snapshot 不完整、K 线过少时的安全行为。

### IV. Provider 和会话边界清楚
产品概念是 K 线图 Agent，不是某个 provider。Codex、OpenAI API、Anthropic 或本地模型都只能作为 LLM provider adapter。Agent session 必须由应用本地保存，并在每次请求中显式构造上下文，不能把 provider 远端 session 当成唯一状态来源。

### V. 行为必须可验证
凡是用户可见行为、配置规则、provider 解析、K 线缓存、策略信号、Agent session 或 API 状态流转发生变化，都必须有对应验证。纯文档修改可以不补测试，运行时行为改动必须跑相关单测或构建。

## 产品约束

- 当前运行形态是 Python 后端加本地浏览器 UI。
- 当前主数据源是 Bitget 和 Alpaca；Longbridge 只作为 legacy 待清理代码，不作为新功能依赖。
- 核心流程必须继续支持本地文件配置。
- 新增持久化优先使用本地文件或 SQLite，不默认上远端数据库。
- 输出只用于行情研究和图表解释，不做下单、仓位管理或收益承诺。

## Agent 与数据源边界

- Agent 输入必须来自结构化 quote、OHLCV K 线、本地策略信号和用户问题，不使用截图识别作为主路径。
- Agent 输出必须是可序列化的结构化分析，包含摘要、方向、置信度、关键价位、观察计划、失效条件和风险说明。
- Provider 失败、凭证缺失或 token 过期时，只影响 Agent 面板，不得阻塞行情和本地策略信号。
- Longbridge 删除要作为独立任务处理，不能在其他功能里顺手半删。

## 流程与质量门禁

- 非小修小补的功能，先写 `specs/` 下的 spec，再写代码。
- 影响多个模块的功能，必须补 plan 和 tasks。
- spec / plan / tasks 都要写清楚：如何处理脏行情，如何保持 provider 边界，如何验证会话行为。
- 没有明确理由的大重构，review 直接拒绝。
- 合并前必须跑完相关测试，并记录验证结果。

## 治理

这份宪法高于临时口头约定。之后的 spec、plan、tasks、review、实现总结都要按它检查。修改规则需要用户明确要求，或者在新 spec / plan 里解释为什么旧规则不再适用。版本号按语义化版本管理：大改动升 major，新增原则升 minor，文字澄清升 patch。
