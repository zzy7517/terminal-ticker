# Tradex UI 与布局重构方案

状态：Draft，待讨论
范围：仅视觉系统、信息层级、页面布局与响应式行为
不包含：业务能力、数据结构、接口、路由语义、Agent 行为、交易逻辑

## 1. 背景

Tradex 保留等宽数据字体与高信息密度，但界面层采用 Codex 式中性灰阶和柔和圆角。颜色只服务于真实的行情与系统语义，不承担装饰性品牌表达。

当前体验不够舒适的主要原因不是配色，而是不同区域拥有近似的视觉权重：行情、会话列表、Agent 工具栏、正文、输入区和边框都在同时争夺注意力。页面能够高效展示信息，但缺少稳定的视觉中心。

本方案参考 OpenAlice 和 Codex，但只提取可迁移的原则：

- OpenAlice：清楚的区域职责、稳定的多栏骨架、日夜模式下相同的空间关系。
- Codex：单一阅读轴线、克制的页面 chrome、正文与输入框对齐、上下文面板主动退后。
- Tradex：高密度交易信息、终端气质、清楚的多工作区入口。

## 2. 设计目标

1. 用户进入 Agent 页面后，第一眼看到正在进行的分析，而不是面板边框和操作按钮。
2. 长篇中文回答保持舒适行宽，数字、表格和工具调用仍保留终端精度。
3. 全局工具栏、会话栏、正文和输入区形成明确的三级密度，而不是全页面同一密度。
4. 1280px、1440px、1920px 及以上桌面宽度都能维持可用的主内容空间。
5. Agent 和 News 采用阅读型布局；Positions、Options 等页面继续使用全宽数据型布局。
6. 第一版聚焦日间模式，先验证布局、层级和阅读体验；夜间模式延期。

## 3. 核心原则

### 3.1 一个页面只有一个视觉中心

Agent 页面以正文阅读列为视觉中心。全局工具栏和会话栏持续可用，但降低对比度。连接状态、token、模型和时间等元数据不得比正文标题更醒目。

### 3.2 不统一密度，按任务分区

| 区域 | 密度 | 字体策略 | 主要表达方式 |
| --- | --- | --- | --- |
| 全局工具栏 | 中 | UI 字体，品牌可用等宽 | 图标、标签、低对比选中态 |
| 会话栏 | 中 | UI 字体为主，元数据等宽 | 选中背景、轻分隔、截断 |
| Agent 正文 | 低 | 中文 UI 字体，数字与代码等宽 | 留白、字号、行宽 |
| 输入区 | 中 | UI 字体 | 清楚边界、低权重操作 |
| Market 工作区 | 高 | 等宽 | 紧凑行、数字对齐、语义涨跌色 |
| Positions / Options | 高 | 等宽 | 全宽网格与表格 |
| Settings | 中 | UI 字体，技术值等宽 | 分组、标签、表单对齐 |

### 3.3 通过空间建立层级

优先使用背景层级、间距、字号和对齐。边框只用于真正的区域边界、表单控件和数据网格。Agent 主区不使用彩色强调边框。

### 3.4 视觉风格保持 Tradex 自己的语言

继续保留：

- 中性石墨灰交互强调。
- Absolutely 浅色主题的 `#CC7D5E` 仅用于开关、输入焦点和主要操作按钮。
- 零圆角或近零圆角系统。
- Market 数字与元数据的等宽字体。
- 冷静、专业、低装饰的终端气质。

不引入：

- OpenAlice 的蓝色选中态。
- Codex 的消费级大圆角和悬浮阴影。
- 装饰性网格背景。
- 玻璃效果、渐变光晕和大面积卡片。

## 4. 页面骨架

### 4.1 全局工作区

~~~text
┌──────────────┬──────────────────────────────────────────────────────┐
│ 左侧工具栏   │ 当前工作区顶部栏                                     │
│ Global Nav   ├──────────────────────────────────────────────────────┤
│              │ 当前工作区内容                                       │
│              │                                                      │
└──────────────┴──────────────────────────────────────────────────────┘
~~~

固定左侧工具栏成为应用的全局导航。它承担当前横向 Workspace 标签、品牌入口和 Settings 入口的职责。当前工作区顶部只保留页面标题、状态和上下文操作，目标高度为 48-56px。

左侧工具栏建议宽度为 208-224px，包含：

- Tradex 品牌。
- Agent。
- Market。
- News、Social、Calendar。
- Positions、Options、Cron。
- Settings。
- 底部连接状态或其他全局状态。

工具栏使用图标加短标签。当前工作区采用浅灰背景和深灰文字，不使用彩色填充。第一版不增加工具栏折叠按钮。

### 4.2 Agent 工作区

~~~text
┌──────────────┬──────────────┬───────────────────────────────────────┐
│ 全局工具栏   │ 会话栏       │ Agent 主画布                          │
│ 208-224px    │ 240-260px    │                                       │
│              │              │        ┌ 阅读轴线 840-920px ┐         │
│              │              │        │ 工具栏             │         │
│              │              │        │ 对话与分析         │         │
│              │              │        │ 输入区             │         │
│              │              │        └────────────────────┘         │
└──────────────┴──────────────┴───────────────────────────────────────┘
~~~

Agent 主画布占满剩余空间，但正文和输入区共享一个居中的阅读轴线。

会话栏保持常驻，不新增折叠按钮。它属于 Agent 工作区的上下文导航，而不是全局导航。

#### Agent 顶部工具栏

将当前分散的标题、上下文占用、运行状态、时间、token 统计和模型选择压缩为两层：

- 第一层：Agent Session、运行状态、上下文占用。
- 第二层：模型选择、时间与 token 统计。

两层总高度控制在 64px 内。元数据使用低对比文本，不使用多个独立 badge 争夺注意力。

#### Agent 正文

- 正文最大宽度：880px，允许在 840-920px 范围内调校。
- 普通中文正文使用 UI 字体，行高约 1.65-1.75。
- 数字、代码、工具名和表格使用等宽字体。
- Assistant 消息默认不使用完整卡片边框。
- User 消息可以保留紧凑背景块，但最大宽度不超过阅读列的 70%。
- 表格、图表和宽代码块允许突破阅读宽度，但不得突破 Agent 主画布。
- 多条工具调用折叠为低权重过程区，不抢占最终回答的层级。

#### 输入区

- 与正文阅读轴线等宽。
- 位于 Agent 主画布底部，不横跨会话栏。
- 输入框自身承担主要边界。
- 附件、模型或其他辅助操作放在输入框底部工具行。
- 发送按钮为局部中性深灰操作按钮，不使用彩色 CTA。
- 空状态和已有会话使用同一个输入区结构，避免布局跳变。

### 4.3 Market

行情不再常驻所有页面。用户通过左侧工具栏进入独立 Market 工作区。

- 复用现有行情数据、分组、选择和管理能力，不新增市场功能。
- Market 主区使用全宽高密度布局。
- Watchlist、市场分组和行情详情在该工作区内重新排布。
- 离开 Market 后不保留行情栏占用，Agent、News 和 Settings 获得完整主区宽度。
- 本轮只移动现有 UI 的位置，不改变行情选择对其他工作区的现有语义。

### 4.4 News 与 Social

News 和 Social 使用阅读型主画布，但不强制复用聊天消息样式。

- 内容列建议最大宽度 1040px。
- 新闻正文或详情使用 760-840px 阅读宽度。
- 列表可以全宽，详情不得无限拉长。

### 4.5 Positions、Options、Calendar 与 Cron

这些页面属于数据型工作区，不使用 Agent 的居中阅读列。

- 使用剩余空间全宽布局。
- 维持等宽数字、紧凑行高和明确数据对齐。
- 页面标题与工具栏沿用全局工作栏节奏。
- 不为了视觉统一将数据表包进大卡片。

### 4.6 Settings

Settings 位于全局工具栏中。进入后采用“全局工具栏 + 设置导航 + 设置内容”的三级结构。

- 设置导航宽度：200-220px。
- 主表单内容最大宽度：1080-1160px。
- Provider 列表与详情允许形成内部双栏，但整个页面最多出现三级视觉层级。
- 标签位于输入控件上方，辅助文本位于下方。
- 技术值使用等宽字体，说明文字使用 UI 字体。

## 5. 响应式空间预算

| 视口宽度 | 全局工具栏 | 会话栏 | Agent 阅读列 | 行为 |
| --- | ---: | ---: | ---: | --- |
| >= 1720px | 224px | 260px | 920px | 完整三栏，主画布留有呼吸空间 |
| 1440-1719px | 216px | 248px | 840-880px | 完整三栏，压缩外围空白 |
| 1200-1439px | 200px | 224px | 剩余宽度 | 保持三栏，正文不再额外留大边距 |
| 980-1199px | 176px | 208px | 剩余宽度 | 缩短标签与间距，不隐藏现有入口 |
| < 980px | 64px 图标栏 | 顶部紧凑列表 | 单列 | 工具栏只显示图标，会话列表移到顶部 |

第一版不新增“专注模式”、工具栏折叠或会话栏折叠功能。响应式变化由 CSS 完成，所有现有入口始终可达。

## 6. 主题范围

### 6.1 第一版：日间模式

- 使用冷灰白或中性纸白画布，不照搬 OpenAlice 的大面积暖米色。
- 侧栏使用略深的中性灰，主画布保持低噪声。
- 石墨灰交互态保证文字和控件对比度。
- 涨跌色针对浅色背景单独校准。
- 不使用纯黑或纯白作为大面积背景。
- 阴影仅用于真正浮层，普通区域以背景差和细分隔线组织。

### 6.2 夜间模式延期

本轮不设计、不实现、不验收夜间模式，也不加入主题切换入口。布局仍使用语义 token，避免将浅色值散落在组件中，为后续夜间模式保留清晰入口。未来增加夜间模式时，不改变本轮确认的布局尺寸和信息层级。

## 7. 组件层级规范

### Surface 层级

1. Canvas：页面主背景。
2. Sidebar：常驻导航或行情背景。
3. Raised：下拉菜单、弹层和临时上下文面板。

普通消息、设置分组和数据区不自动获得 Raised 层级。

### 边框

- 区域边界：1px 低对比分隔线。
- 输入控件：1px 中对比边框，focus 使用中性石墨灰。
- 选中态：背景色或单侧 2px 标记，避免整圈高亮。
- Agent 主画布：无整圈强调边框。

### 字体

- UI 字体：导航、说明、中文正文、表单标签。
- 等宽字体：行情、价格、百分比、时间、token、模型 ID、代码和表格数字。
- 品牌字标可以继续使用等宽字体。

### 形状

- 采用统一的柔和圆角系统：小标签 6px，按钮与输入框 10px，面板 14px，主要输入组合区与浮层 18px。
- 行情表格和数据网格只对外层容器使用圆角，内部行列保持紧凑。
- 不使用满屏胶囊按钮，也不混用互相冲突的圆角尺度。

## 8. 明确不做

- 不改变现有业务信息架构和路由。
- 不新增交易、Agent、News、Memory 或 Provider 能力。
- 不重写模型回答内容。
- 不新增全局导航之外的业务入口。
- 不在 Agent、News、Settings 等页面常驻行情栏。
- 不新增专注模式、可拖拽布局或用户自定义面板。
- 不引入新的组件库、动画库或设计系统依赖。
- 不把所有页面统一成聊天页面布局。

## 9. 实施计划

### 阶段一：清理实验改动并建立稳定骨架

- 撤销当前未提交的实验性 UI 修改。
- 将品牌、Workspace 标签和 Settings 入口整理为固定左侧工具栏。
- 将现有行情区域迁移到独立 Market 工作区。
- 按响应式空间预算调整工具栏、会话栏与 Agent 主画布。
- 去掉 Agent 主面板的整圈强调边框。

阶段完成后，现有功能必须全部可用，其他工作区不得发生布局回归。

### 阶段二：建立 Agent 阅读轴线

- 限制正文宽度并居中。
- 让输入区与正文对齐。
- 调整 Assistant、User、工具调用、表格与代码块的视觉层级。
- 压缩 Agent 顶部元数据区域。

阶段完成后，长回答、空状态、加载状态和流式回答都必须保持稳定。

### 阶段三：统一其他页面与设置页节奏

- News 与 Social 应用阅读型布局。
- Positions、Options、Calendar 与 Cron 保持全宽数据型布局。
- Settings 应用统一的表单宽度、标签和辅助文本节奏。

阶段完成后，每类页面都应符合自己的密度模型，而不是共享同一套卡片布局。

### 后续阶段：夜间模式

- 定义夜间语义 token。
- 单独校准文字、按钮、表单、涨跌色和 focus 状态对比度。
- 再决定是否加入用户可见的主题切换入口。

该阶段不属于本轮实施范围，可以独立延期。

## 10. 验收标准

### 布局

- 1440px 视口下 Agent 正文可用宽度不低于 840px。
- 1920px 视口下正文行宽不超过 920px。
- 输入框与正文左、右边界对齐。
- Agent 主画布没有整圈彩色强调边框。
- 发送按钮不再成为页面面积最大的强调色块。
- Positions 和 Options 仍可使用主画布全宽。
- Agent、News 和 Settings 页面不显示常驻行情栏。
- Market 可通过左侧工具栏直接进入。

### 可读性

- 中文正文连续阅读时不使用全等宽字体。
- 数字、代码和表格列保持等宽对齐。
- Assistant 回答、User 消息、工具调用和系统状态无需依赖文字内容即可区分。
- 主要正文与次要元数据至少形成两个清晰对比层级。

### 响应式

- 1280px 下不存在正文被两侧栏压缩到不可阅读的情况。
- 980px 以下不出现横向页面滚动。
- 左侧工具栏和会话栏不新增折叠按钮。
- 会话加载、空状态和长标题不会破坏列宽。

### 主题

- 日间模式所有正文、按钮、输入框和状态色达到 WCAG AA。
- 浅色值全部由语义 token 提供，不散落在组件样式中。
- 不出现为了模仿 OpenAlice 而引入的大面积暖米色或蓝色选中态。

## 11. 风险与回滚

### 主要风险

最脆弱的假设是用户可以接受行情从“所有页面持续可见”变为“通过 Market 工作区查看”。如果实际交易流程要求在阅读 Agent 回答时持续观察行情，本方案会降低跨区域监控效率，需要重新评估辅助行情摘要，而不是恢复完整常驻行情栏。

### 回滚策略

- 每个阶段独立提交。
- 不修改 API、store schema 和持久化数据。
- 任一阶段都可以通过回滚对应 CSS 与局部 JSX 恢复。
- 后续夜间模式不与本轮布局修改放在同一个提交中。
