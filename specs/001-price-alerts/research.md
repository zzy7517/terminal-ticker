# 设计取舍：价格提醒

## 1. 提醒配置继续走现有 watchlist

- **结论**：提醒规则直接放在每个 symbol 的配置里。
- **原因**：现有项目已经依赖本地 TOML，没有必要再造第二套配置入口。
- **不选方案**：
  - 窗口内编辑器：v1 太重。
  - 单独 alert 文件：会把配置拆散。

## 2. v1 只做窗口内视觉提醒

- **结论**：先只在悬浮窗内部提示。
- **原因**：最轻，最符合当前产品定位。
- **不选方案**：
  - 系统通知：会引入平台差异。
  - 声音提醒：噪音太大，也不利于测试。

## 3. 只对“观察到的新鲜穿越”触发提醒

- **结论**：只有价格从阈值一侧真实跨到另一侧，且这笔价格是新鲜行情，才提醒。
- **原因**：这样可以避免启动误报和重连误报。
- **不选方案**：
  - 启动时只要已在阈值外就提醒：会误报。
  - 重连后第一笔已在阈值外就提醒：也会误报。

## 4. 价格回到另一侧后自动重新 arm

- **结论**：提醒触发一次后，如果价格回到另一侧，下次再穿越可以再次提醒。
- **原因**：这样不需要做额外的“手动重置提醒”交互。
- **不选方案**：
  - 一次性规则：需要多做状态管理。
  - 每笔都提醒：会刷屏。
